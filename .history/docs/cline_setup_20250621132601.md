# Cline + Ollama セットアップガイド

## 概要

このドキュメントでは、有研東京検査所 精度管理システムでCline拡張機能とOllamaを使用したAI支援コーディング環境のセットアップ方法を説明します。

## 前提条件

- macOS 10.15以降
- Homebrew（パッケージマネージャー）
- VS Code
- Python 3.8以降

## セットアップ手順

### 1. Ollamaのインストール

自動セットアップスクリプトを使用：

```bash
# プロジェクトルートディレクトリで実行
./scripts/setup_ollama.sh
```

または、手動でインストール：

```bash
# Homebrewを使用してOllamaをインストール
brew install ollama

# Ollamaサービスを開始
ollama serve
```

### 2. 推奨モデルのダウンロード

```bash
# コード生成に最適なモデル
ollama pull codellama:7b

# 汎用モデル
ollama pull llama3.2:7b

# 軽量モデル（高速処理用）
ollama pull llama3.2:3b
```

### 3. Cline拡張機能のインストール

1. VS Codeを開く
2. 拡張機能タブ（Ctrl+Shift+X）を開く
3. "Cline"を検索
4. Cline拡張機能をインストール

### 4. 設定の確認

プロジェクトには以下の設定ファイルが含まれています：

- `.cline/config.json` - グローバル設定
- `.cline/project.json` - プロジェクト固有設定

## 使用方法

### 基本的な使用方法

1. **コード生成**
   - ショートカット: `Cmd+Shift+G`
   - 要件を記述してコードを生成

2. **コード説明**
   - ショートカット: `Cmd+Shift+E`
   - 選択したコードの動作を説明

3. **コードリファクタリング**
   - ショートカット: `Cmd+Shift+R`
   - コードの改善提案

4. **デバッグ支援**
   - ショートカット: `Cmd+Shift+D`
   - エラーの原因分析と解決策

5. **テスト生成**
   - ショートカット: `Cmd+Shift+T`
   - コードのテストケース生成

## 設定のカスタマイズ

### モデルの変更

`.cline/project.json`ファイルでモデルを変更できます：

```json
{
  "model_config": {
    "provider": "ollama",
    "model": "codellama:13b",  // より高性能なモデル
    "temperature": 0.2,        // より決定論的な出力
    "max_tokens": 4096         // より長い出力
  }
}
```

### プロンプトのカスタマイズ

`.cline/config.json`ファイルでプロンプトをカスタマイズできます：

```json
{
  "prompts": {
    "code_generation": "あなたのカスタムプロンプト",
    "code_explanation": "あなたのカスタムプロンプト"
  }
}
```

## トラブルシューティング

### Ollamaが起動しない

```bash
# Ollamaプロセスを確認
ps aux | grep ollama

# Ollamaを再起動
pkill ollama
ollama serve
```

### モデルがダウンロードできない

```bash
# 利用可能なモデルを確認
ollama list

# モデルを再ダウンロード
ollama pull codellama:7b
```

### Clineが応答しない

1. VS Codeを再起動
2. Cline拡張機能を無効化して再有効化
3. 設定ファイルの構文を確認

## ベストプラクティス

### 1. プロンプトの書き方

- **具体的な要件を記述**
  ```
  ❌ 悪い例: "データベースクラスを作成"
  ✅ 良い例: "SQLiteデータベースでQCデータを管理するクラスを作成。CRUD操作、エラーハンドリング、ログ出力を含む"
  ```

- **コンテキストを提供**
  ```
  ✅ 良い例: "このコードはStreamlitアプリケーションの一部で、QCデータの入力フォームです"
  ```

### 2. コードレビュー

- 生成されたコードは必ずレビューする
- セキュリティ、パフォーマンス、可読性を確認
- プロジェクトのコーディング規約に従っているか確認

### 3. 段階的な開発

- 大きな機能は小さな部分に分割
- 各段階でテストを実行
- 継続的に改善
