# データベース設計書

## 1. データベース概要

### 1.1 データベース構成

本システムは、**マスターデータ**と**測定結果データ**を分離して管理します。

#### 1.1.1 マスターデータベース（SQLite3）

- **データベース名**: `master_data.db`
- **データベース種別**: SQLite 3.x
- **保存場所**: `db_folder/master_data.db`
- **用途**: 担当者、測定機器、測定パネル、QC_Controlのマスターデータ管理
- **管理ページ**: `pg99_master_table`
- **機能**:
  - データの直接入力・更新
  - Excelファイルからのインポート
  - Excelファイルへのエクスポート

#### 1.1.2 測定結果データベース（DuckDB）

- **データベース名**: `qc_data_base.db`
- **データベース種別**: DuckDB
- **保存場所**: `db_folder/qc_data_base.db`
- **用途**: 測定結果のエクセル表データの管理・操作
- **管理ページ**: `pg01_qc_check`, `pg02_test_status`, `pg03_qc_act_log`, `pg04_confirmation_of_accuracy_control`, `pg05_statical`
- **機能**:
  - Excelファイルからの測定結果データの取り込み
  - 測定結果データの操作・分析

### 1.2 データ読み込み方針

各ページでのデータ読み込み方針：

- **マスターデータ（担当者、測定機器、測定パネル、QC_Control）**: SQLite3（`master_data.db`）から読み込み
- **測定結果のエクセル表**: DuckDB（`qc_data_base.db`）から読み込み・操作

### 1.3 用途

有研東京検査所の精度管理システムにおける測定データ、判定結果、ログ情報の管理

## 5. データベース間の関係

### 5.1 マスターデータベース（SQLite3）と測定結果データベース（DuckDB）の関係

- マスターデータベース（SQLite3）は、測定結果データベース（DuckDB）から参照される参照データを管理
- 測定結果データベース（DuckDB）は、マスターデータベース（SQLite3）のデータを参照してデータの整合性を保つ
- 両データベースは独立しており、物理的な外部キー制約は存在しないが、アプリケーションレベルで整合性を保つ

### 5.2 測定結果データベース（DuckDB）内のテーブル間の関係

- `table_qc_file_info` ←→ `table_qc_ic`, `table_qc_nc`, `table_qc_pc`（File_Nameで関連）
- `table_qc_file_info` ←→ `table_qc_status_log`（File_Nameで関連）
- `table_qc_file_info` ←→ `table_qc_multi_rule`（File_Nameで関連）
- `table_qc_file_info` ←→ `table_qc_act_log`（File_Nameで関連）

## 6. データ整合性

### 6.1 マスターデータベース（SQLite3）の制約

- 主キー制約：各テーブルのidカラム
- UNIQUE制約：重複データ防止（必要に応じて）

### 6.2 測定結果データベース（DuckDB）の制約

- 主キー制約：各テーブルの主キーカラム
- UNIQUE制約：重複データ防止（PRIMARY KEYで定義）
- アプリケーションレベルでの整合性チェック：マスターデータとの整合性を保つ
